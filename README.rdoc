== README

= Schengen Calculator

A Rails application for tracking the Schengen 90/180-day rule.

The bundle loads the Rails frameworks used by the calculator, mail and WebSocket
support explicitly. Active Storage, Action Mailbox and Action Text are not
installed: the application has no upload or rich-text features.

Live site: https://schengen-calculator.com


== Local setup

Requirements:
* Ruby 4.0.9
* PostgreSQL (the included Docker Compose configuration can provide it)
* Chrome and ChromeDriver for browser tests

From the repository root:

  cd src
  rvm use ruby-4.0.9
  bundle install
  cp config/secrets.yml.example config/secrets.yml
  docker compose up -d postgres
  bundle exec rails db:prepare
  bundle exec ruby bin/dev

Use another Ruby version manager if preferred; <tt>src/.ruby-version</tt> is the
source of truth. Open http://localhost:3000/en/about after the server starts.

<tt>bin/dev</tt> regenerates the country catalogues before starting Rails. Restart
it after changing country data or translations. If starting Rails another way,
run <tt>bundle exec rails country_catalog:generate</tt> first.

<tt>db:prepare</tt> initializes and seeds a new local database or migrates an
existing one. Do not run <tt>db:seed</tt> against valuable data: this project's
seed file deletes existing users, people, countries, and continents before
loading sample data.

If stale precompiled assets hide local CSS or JavaScript changes, run:

  bundle exec rails assets:clobber


== Frontend assets

Bootstrap 5.3 styles are compiled with Dart Sass through
<tt>dartsass-sprockets</tt>. Sprockets fingerprints and serves the CSS,
JavaScript, images, and Font Awesome fonts; no separate Node package build is
required. Run <tt>bundle exec rails assets:precompile</tt> to verify the build.

Keep Bootstrap data attributes namespaced as <tt>data-bs-*</tt>. jQuery and
<tt>jquery_ujs</tt> remain in use for remote Rails forms and existing calculator
interactions. Bootstrap's jQuery bridge is available, but component instances
must be read with Bootstrap's <tt>getInstance</tt> API rather than jQuery data.
Font Awesome Free 7 is self-hosted under <tt>src/vendor/assets</tt>. Its Sass
modules use the same Dart Sass compiler, and Sprockets fingerprints its WOFF2
fonts. See the vendored asset README for version, license and update instructions.

Shared deferred startup lives in <tt>third_party_scripts.js</tt>, while
<tt>adsense.js</tt> owns SDK loading and slot requests in the core bundle. Views
provide public configuration through data attributes and render
<tt>adsense-slot</tt> placeholders; the initializer adds Google's class
and requests each slot once the SDK is loaded and the slot is visible with a
positive width. Pending slots are observed for responsive layout changes. Keep
ad requests out of individual views.


== Configuration

Development and test settings are loaded from <tt>src/config/secrets.yml</tt>
through <tt>AppConfig</tt>. Production secrets are loaded from AWS Systems
Manager Parameter Store; see <tt>deployment/README.md</tt> for the required
parameters and infrastructure configuration.


== Country data

<tt>src/db/data/countries.xml</tt> is the source of truth for country codes,
names, Schengen membership dates, and visa requirements. After changing it, run
from <tt>src</tt>:

  bundle exec rails db:update_countries
  bundle exec rails country_catalog:generate

The first command updates persisted country records. The second regenerates the
localized, file-backed country catalogues used to render public pages without a
database query. Deployments update the database and build the catalogues into
the Lambda image automatically. Catalogue JSON is generated locally and ignored
by Git; do not edit it directly. CI generates it before tests and cache warm-up.


== Translations

The application supports English, German, Spanish, French, Hindi, Turkish,
Simplified Chinese, Brazilian Portuguese, and Arabic. Locale files live in
<tt>src/config/locales</tt>.

From <tt>src</tt>:

  bundle exec rails i18n:check
  bundle exec rails i18n:add_placeholders
  bundle exec rails i18n:remove_unused
  bundle exec rails i18n:normalize

Add English strings first, generate placeholders, translate every
<tt>[TRANSLATE]</tt> value, then run <tt>i18n:check</tt>. Dynamic keys that cannot
be detected statically are configured in <tt>src/config/i18n-tasks.yml</tt>.


== Tests

With PostgreSQL running, run the Rails suite from <tt>src</tt>:

  RAILS_ENV=test bundle exec rails db:prepare
  RAILS_ENV=test bundle exec rails country_catalog:generate
  bundle exec rails test

Run a focused test by passing its path to <tt>bundle exec rails test</tt>.

Run infrastructure and header JavaScript tests from <tt>deployment</tt>:

  npm ci
  npm run build
  npm test -- --runInBand


== Public page rendering

Cacheable public pages render without SQL so anonymous traffic does not wake the
database. They use the generated <tt>CountryCatalog</tt> and a lightweight draft
person for presentation, resolving country codes to Active Record objects only
when submitted data is saved. A cold-render integration test enforces this
boundary across every supported locale.

Cached public pages fetch personalized header state only when
<tt>has_calculator_session=1</tt> or <tt>has_flash_message=1</tt> is present.
Anonymous visitors make no <tt>/session_header</tt> request. Older sessions
without a hint cookie keep the generic header until a dynamic calculator route
restores the hint.

Public <tt>/visits</tt> and <tt>/days</tt> pages always ignore session cookies.
CloudFront removes cookies before their cache lookup, and the public controller
subclasses never resolve a user or nationality session. Personal calculations
use explicitly uncached <tt>/my/visits</tt> and <tt>/my/days</tt> routes, including
localized URLs. These validate signed user, guest or nationality state before
running a calculator; visitors without that state return to the public page.
Forms keep their original mutation endpoints and redirect back to private
state when appropriate. Public CSV URLs redirect to the private export.

On public calculator pages, the header endpoint can return a private
continuation only after validating the session. JavaScript accepts only the
expected local route and preserves calendar presentation parameters. Flash
messages are kept for that destination. The static My calculator link also
works without JavaScript or when a browser has lost its hint cookie.

Trips and Calendar reads preserve stored visits. Their displayed calculations,
calendar helpers, and new-trip defaults use the supported ±20-year date window
without deleting records outside it. Date validation still applies to new and
updated visits. Retained history still counts toward a visa's lifetime entry
limit. Scheduled guest-account cleanup runs separately from page views.

The header endpoint returns flash messages as plain text, which JavaScript
renders with <tt>textContent</tt>. Menu fragments pass through the locally
vendored DOMPurify sanitizer before insertion, with only the menu's required
markup and localized link/form routes allowed. Keep logout as a native submit
button and keep event handlers out of menu HTML. See the DOMPurify vendor README
for its version and manual security-update instructions.

Account deletion requires a signed-in registered user. Guest and anonymous
requests to the account-deletion endpoint receive HTTP 403, including requests
with a valid CSRF token. Registered users retain CSRF-protected deletion of
their own account and its travel records.


== Facebook OAuth

Set the Facebook App Domains to <tt>schengen-calculator.com</tt>,
<tt>www.schengen-calculator.com</tt>, and <tt>test.schengen-calculator.com</tt>,
then configure these callback URLs:

* https://schengen-calculator.com/users/auth/facebook/callback
* https://www.schengen-calculator.com/users/auth/facebook/callback
* https://test.schengen-calculator.com/users/auth/facebook/callback
* http://localhost:3000/users/auth/facebook/callback

CDK enables <tt>FACEBOOK_WEB_LOGIN_WORKAROUND</tt> in staging and production to
keep the OAuth handoff in Android Chrome. The OAuth request must remain POST- and
CSRF-protected.

Facebook sign-in identifies an existing account only by its provider and user
ID. Matching an email address never links an existing account automatically.
If that email is already registered, the user must sign in with the existing
password or recover the account through its password-reset flow. Review any
account links created before this safeguard if account pre-hijacking is
suspected; this change does not establish ownership of historical links.

Production mail links use HTTPS and the deployment's <tt>DOMAIN</tt>, with
<tt>schengen-calculator.com</tt> as the default. SMTP on port 587 requires
STARTTLS and certificate verification; missing TLS or an invalid certificate
causes delivery to fail. If prior plaintext exposure is suspected, rotate the
SMTP credential and invalidate outstanding recovery tokens as part of the
incident response.

Password recovery uses its own layout without analytics, advertising, social
SDKs, or JavaScript. Recovery responses, including validation errors and
redirects, send <tt>Referrer-Policy: no-referrer</tt> and private/no-store
caching. Their content policy permits only local styles, fonts, images, and
form submissions. Keep third-party resources out of this layout so recovery
tokens cannot reach them through referrers or page scripts.

Recovery requests normalize recipient emails and apply a ten-minute recipient
cooldown, five deliveries per recipient per UTC day, ten requests per client
per 15 minutes, and a shared budget of 100 deliveries per hour. IPv6 privacy
addresses share a /64 network bucket. Recipient and network identifiers are
HMAC-blinded in the limiter store, and email parameters are filtered from logs.
Existing and unknown accounts, including suppressed recipient requests, get the
same confirmation. Client throttling returns HTTP 429; unavailable limiter
storage returns HTTP 503 before token replacement or mail. Recovery remains a
native, CSRF-protected Devise flow with paranoid responses enabled globally.
Auth routes receive an identity-only edge
function that overwrites viewer IP headers without changing OAuth URLs.

Guest calculation links use the same protected layout. Opening a link never
adopts its guest identity. An explicit, CSRF-protected confirmation consumes
the link once and imports an independent copy. Existing travelers are kept;
registered accounts receive additional travelers, while anonymous browsers
receive a private guest calculator. Later edits are never written back to the
shared source, even if another browser previously accessed it. Legacy
<tt>guest_calculation</tt> query links lead to the same confirmation flow.
CloudFront redirects both Trips and Calendar query links before serving any
HTML. Ordinary pages use <tt>strict-origin-when-cross-origin</tt>, preserving
local calendar return navigation while keeping paths and queries out of
cross-origin referrers. Token confirmation and recovery pages keep their
stricter <tt>no-referrer</tt> policy.
An import copies at most 20 travelers and 500 visits/visas in total, including
any existing guest data that must be preserved. Oversized imports fail without
changing the current calculator or consuming the link.


== Calculation API availability

Calculation creation requires the shared database rate limiter. Missing tables,
connection failures and other limiter database errors return HTTP 503 with a
60-second <tt>Retry-After</tt> and save no calculation records. The usual
30-request/10-minute quota still returns HTTP 429 when exhausted. A store outage
never grants a fresh quota or bypasses the limiter.

Guest web allocations share a 30-request/10-minute limit per verified client IP
and per existing guest account across trips, visas, travelers and claim imports.
Throttled requests return HTTP 429 before allocating a guest or travel records;
limiter outages return HTTP 503. Changing sessions or viewer-supplied identity
headers does not reset the IP quota. Registered accounts keep their normal saves.

Guests retain at most 20 travelers and 500 combined trips/visas across all their
travelers. Every model insert checks capacity while holding the guest user's
database row lock, so concurrent writers cannot pass separate count checks.
Imports use the same bounds and lock their source/existing guest in ID order
before copying. Existing records remain readable, editable and removable;
deletion frees space. Keep guest creation checks before password hashing and
keep cached public GETs free of limiter writes.

Guest calculation reads share a 60-request/minute quota per verified client IP
and guest account across Trips, Calendar and calendar lookups. Anonymous cached
pages do not consume this quota or query its store. Read quotas also fail closed.
Guests whose active traveler already exceeds the record cap get a private,
non-calculating management page with at most 100 trips and 100 visas per page.
Cursor navigation and CSRF-protected deletion remain available until the data
fits the calculation limit; reads never prune legacy records.

Each calculation owns one visa-history snapshot. It preloads applicable visas
and retained visits/countries once, computes entry counts once per visit and
reuses them in row rendering and CSV. Calendar counts use indexed entry timelines
and direct date lookups, preserving retained visa history without repeated
database queries or day-array copies. Visa boundary precedence matches the
latest applicable visa in the model, with record ID breaking exact date ties.
Same-day border groups preserve each visit's entry count in a linear pass.
Do not cache derived visa state on persistent
model instances. Day generation is bounded in days to the supported 40-year
window plus the 190-day forecast; oversized direct-service spans raise an error.

== Deployment

The Rails web app, private database operations, and MCP server run as
container-based AWS Lambda functions behind API Gateway and CloudFront. GitHub
Actions deploys the staging and production CDK stacks, runs migrations, verifies
the deployed application, and refreshes the edge cache.

Both HTTP API origins require AWS IAM signatures generated by a dedicated
Lambda@Edge function. Rails and MCP trust viewer identity only from that role's
verified API Gateway context. The retired SSM origin bearer grants no access
after deployment. The edge stack runs in <tt>us-east-1</tt>; application stacks
run in <tt>eu-central-1</tt>. See the deployment guide for bootstrap requirements,
request-size limits and verification gates.

Calculator cache misses share a per-network request quota at the edge before
Rails runs. A separate on-demand DynamoDB counter in each environment enforces
the limit across replicas; excessive requests receive 429 and storage failures
receive 503. Public cache hits and private-session cache rules are preserved.
The signer filters headers and cookies using trusted per-behavior profiles
before authenticating requests to the origin.

Pin external GitHub Actions to full commit SHAs and retain version comments.
Disable checkout credential persistence in jobs that do not push commits.
Dependabot checks for Actions updates weekly using <tt>.github/dependabot.yml</tt>.

See the {deployment guide}[deployment/README.md].
